### Security: forms from other sites are refused (upgrade notes)

Jethro now asks the browser where each form submission came from, using the
`Sec-Fetch-Site` and `Origin` headers that browsers add themselves, and refuses
submissions that came from another website. This replaces the hidden one-time
tokens on the login and person-edit forms, which have been removed.

What users notice:

- **No more "Login form expired".** It appeared after a browser restart, with
  several tabs open, or when the members login is shown inside another website
  (an iframe), and pressing Log In again was the only fix.
- **Reloading the 2-factor code page** no longer re-sends your password or
  another SMS code.

What may need attention when you upgrade:

- **Scripts that log in through the login page** (curl, wget, Python, etc.)
  must now send an `Origin` header naming your Jethro site, or
  `Sec-Fetch-Site: same-origin`, and no longer need to scrape `login_key`. The
  field is gone, so scripts that look for it will fail. For example:

  ```bash
  curl -c jar -b jar -L -H 'Origin: https://jethro.example.org' \
    --data-urlencode username=... --data-urlencode password=... \
    https://jethro.example.org/
  ```

  A login that sends neither header shows "Your browser did not confirm this
  login came from this site".
- **Scripts that submit other forms** keep working if they send no `Origin`,
  `Referer` or `Sec-Fetch-Site` headers. If they send one that names a
  different site, they now get `403 Forbidden`.
- **Forms hosted on another website**, such as a login form copied into your
  church website's HTML, are refused with `403 Forbidden`. This includes
  another site on your own domain (e.g. `www.church.org` posting to
  `jethro.church.org`). Showing Jethro's own members page in an iframe still
  works, as does linking to it.
- **Behind a reverse proxy or load balancer** that handles HTTPS or rewrites
  the `Host` header, define `TRUST_X_FORWARDED_HEADERS` in `conf.php` so
  Jethro knows its public address, and list that hostname in `ALLOWED_HOSTS`
  if you use it. Otherwise requests that carry `Origin` but not
  `Sec-Fetch-Site` (older browsers, and scripts like the one above) are
  refused, because their origin doesn't match the address Jethro sees.

Refusals are written to the web server's PHP error log, as
`Blocked POST <url>: request came from another origin (Sec-Fetch-Site=...)` or
`Refused staff login: browser did not confirm a same-origin request (...)`
(`members login` for the members area). See
[Request origin protection](../developer/reference/request-origin-protection.mdx)
for the full rules.
